# Бот «IT РОСТ» — MAX + AlfaCRM

Бот инженерно-технического направления **IT РОСТ** (г. Волжский, на базе
МОУ «СШ № 5 имени С.П. Королёва») для мессенджера **MAX**, работающий
поверх **AlfaCRM**, филиал **2**.

Три роли: родитель, преподаватель, менеджер. Плюс воронка для новых
посетителей, которых в CRM ещё нет.

---

## Откуда он взялся

Это сборка из двух рабочих проектов:

* транспорт MAX, диспетчер, FSM, клавиатуры, воронка новых клиентов,
  уведомления менеджеру — из бота «Колибри» (MAX + impulseCRM);
* работа с AlfaCRM — из более раннего бота на Telegram/aiogram.

Слой CRM вынесен в `alfacrm_client.py` с тем же набором методов, что был
у `impulse_client.py`, поэтому кеш, планировщик и все хендлеры остались
без изменений логики.

### Что стало проще по сравнению с версией на impulseCRM

| | impulseCRM | AlfaCRM |
|---|---|---|
| Занятие | `schedule` — **правило повторения** («по вторникам 16:00 с 25.08 по 29.12»); бот разворачивал его в даты и выдумывал id вида `116:2026-09-01` | `lesson` — конкретное занятие с настоящим id |
| Состав учеников | вычислялся через абонементы, записи и членство в группах (`STRICT_ENROLLMENT`) | берётся прямо из `lesson.customer_ids` |
| Тема / ДЗ / статус | таких полей нет — только в SQLite бота | есть на `lesson`, бот **пишет их обратно в CRM** |
| Посещаемость | недокументированный внутренний API веб-интерфейса; **не принимает API-ключ**, требует вручную подставлять cookie сессии браузера и обновлять её по мере протухания | документированное поле `lesson.details` (`is_attend`, `reason_id`), обычный `lesson/update` с обычным токеном |
| Счётчик заморозок | прятался в поле **адреса** клиента — «ул. Ленина, д. 5» могла быть прочитана как пять заморозок | отдельное дополнительное поле `custom_*` или база бота |
| Имена полей | ~40 переменных окружения, потому что схема не публикуется | зашиты в клиент |
| Признак «действующий ученик» | отсутствует | штатный `is_study` |

## Установка

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt

copy .env.example .env
notepad .env          # заполнить MAX_BOT_TOKEN, ALFACRM_*, ADMIN_MAX_IDS
```

Проверить связку с CRM, не запуская бота:

```powershell
python alfa_probe.py
python alfa_probe.py --phone +79001234567
```

Запуск:

```powershell
python main.py
```

В первых строках лога печатается версия сборки и филиал — по ним видно,
какой код реально работает на сервере:

```
📦 Версия сборки: it-rost 2026-08-31.1 (MAX + AlfaCRM, филиал 2)
🏢 Филиал AlfaCRM: 2 (https://...)
```

### Как узнать свой MAX id

Напишите боту `/id` — он ответит числом. Впишите его в `ADMIN_MAX_IDS`
и перезапустите бота. Пока список пуст, id пишется в лог при каждом
обращении.

## Что умеет

**Телефон обязателен до любого взаимодействия.** Новый пользователь, менеджер
из `ADMIN_MAX_IDS` и старая учётная запись с пустым номером сначала должны
отправить свой контакт или вручную ввести номер минимум из 10 цифр. Команды,
кнопки и меню до этого заблокированы. Номер сохраняется и повторно в рамках
воронки не запрашивается.

**Родитель** — расписание (сегодня / завтра / неделя / месяц / свой
период), домашние задания с файлами (свои плюс общие для группы),
остаток занятий и беспричинных заморозок, заморозка занятия, переписка
с менеджером прямо в боте, заявка на перенос.

**Преподаватель** — своё расписание, отметка посещаемости кнопками
учеников прямо под карточкой занятия, отметка неявки, заморозка занятия
ученику, адресное ДЗ (всей группе или конкретному ребёнку) текстом и
файлом, отчёт за 30 дней, заявка на перенос.

Отдельной кнопки «занятие проведено» нет: статус ставится сам при первой
отметке посещаемости, иначе абонемент бы не списался. Обработчик старой
кнопки оставлен — сообщения живут в истории чата сколько угодно долго.

Посещаемость, неявки и ДЗ уходят **и в бот, и в AlfaCRM**. Если запись в
CRM не прошла, преподаватель видит явное предупреждение — молчание здесь
опаснее ошибки: он был бы уверен, что занятие закрыто.

**Менеджер** — сводка за период, рассылки по базам (новые заявки /
зарегистрированные / родители / преподаватели / все) с дедупликацией,
обработка заявок на перенос, обращений из поддержки и решений по
неявкам, кнопки «👀 Активность в боте» и «Кто вошёл в бота».

Вход менеджером — по списку `ADMIN_MAX_IDS` или командой `/manager` с
паролем, чтобы подключить сотрудника без правки `.env` и перезапуска.

**Новый посетитель** — `/start` спрашивает, впервые он или уже занимается.
Впервые: рассказ о программах → возраст ребёнка (несколько детей через
пробел) → подходящие программы кнопками, **для каждого ребёнка отдельно**
→ телефон → заявка менеджеру. Черновик заявки пишется в БД на каждом
шаге, поэтому ушедший на середине посетитель всё равно виден менеджеру.

**Автоматически** — расписание на день в 8:00, напоминание за час до
занятия (одно: два сообщения об одном занятии читаются как спам), сводка
менеджеру в 00:01, сводка по неявкам в 21:00, поиск сгоревших занятий
каждые 15 минут, чистка журналов в 3:30.

Про сгоревшие занятия: уведомление уходит только по детям, которых
преподаватель **явно отметил** как не пришедших. Сообщать «занятие
сгорело» на основании отсутствия отметки означало бы регулярно врать
родителям из-за забывчивости преподавателя — такие дети попадают в
вечернюю сводку менеджеру в раздел «никак не отмечены».

## Программы (каталог воронки)

Взяты из утверждённых ДОП, а не с сайта: на сайте они сгруппированы в
«ступени» по классам, а в программах у каждой свой диапазон, и они
перекрываются. По сетке с сайта ребёнок 8 лет не увидел бы
робототехнику, на которую его можно записать.

| Программа | Возраст | Объём |
|---|---|---|
| Scratch-программирование | 7–10 лет (1–4 кл.) | 35 ч, год |
| Робототехника | 8–12 лет (2–6 кл.) | 35 ч, год |
| Python: вводный курс | 10–14 лет (4–8 кл.) | 40 ч, полугодие |
| Шахматы (начинающие) | 7–14 лет (1–8 кл.) | 72 ч, год |
| Шахматы (продолжающие) | 8–15 лет, после начального курса или с разрядом | 72 ч, год |

Свободный набор — 7–14 лет (`MIN_AGE` / `MAX_AGE`). До 15 лет доходит
только группа для продолжающих, куда с улицы не записывают.

Группа для продолжающих **не показывается кнопкой** новому посетителю:
туда зачисляют по итогам начального курса, и родитель, выбравший её
наугад, услышал бы отказ уже на звонке.

Править каталог — `bot/directions.py`, вступительный текст воронки —
`bot/handlers/lead.py` (`WELCOME_TEXT`).

## Структура

```
main.py                 точка входа: клиент CRM -> кеш -> БД -> планировщик -> диспетчер
settings.py             единственная точка чтения окружения
alfacrm_client.py       клиент AlfaCRM v2 API: уроки, посещаемость, абонементы
freezes.py              счётчик беспричинных заморозок (поле CRM или база бота)
alfa_probe.py           диагностика связки с CRM (только чтение)
cache.py                кеш занятий, окно −30/+60 дней, обновление раз в 5 мин
database.py             SQLite: пользователи, заявки, лиды, заметки к урокам, лог напоминаний
scheduler.py            фоновые задания
ssl_utils.py            SSL-контекст с сертификатами Минцифры (нужны для MAX)
certs/                  корневые сертификаты НУЦ Минцифры
max_api/                клиент MAX: client.py, context.py, keyboards.py
bot/
  dispatcher.py         минимальный Router/Dispatcher вместо aiogram
  fsm.py, states.py     состояния диалогов
  formatting.py         карточки занятий, расписание, сводки
  directions.py         каталог программ и подбор по возрасту
  notifier.py           уведомления менеджеру о активности
  handlers/             start, lead, parent, teacher, manager, support, common
```

## Если что-то не работает

**Пустое расписание у всех.** `python alfa_probe.py` — почти всегда
неверный `BRANCH_ID` (для IT РОСТ это 2) или нет занятий в окне кеша.

**Расписание есть у преподавателя, пусто у родителей.** В карточках
уроков AlfaCRM пуст `customer_ids` — ученики не добавлены в занятие. Бот
пишет об этом предупреждением в лог при каждом обновлении кеша.

**Родитель не входит по телефону.** `python alfa_probe.py --phone +7…`.
Сравнение идёт по последним 10 цифрам, так что формат номера роли не
играет; значит, номера в карточке действительно нет.

**Отметки не появляются в CRM.** У API-пользователя нет прав на
изменение уроков. Преподаватель увидит предупреждение под сообщением,
подробности — в логе. В самом боте отметка при этом сохранена.

**Заморозки не видны в CRM.** Не задан `ALFACRM_REASON_EXCUSED` — бот
пишет их только у себя и сообщает об этом в лог при первой заморозке.
Возьмите id уважительной причины из справочника причин пропуска AlfaCRM.

**Остаток заморозок не меняется в карточке ученика.** В AlfaCRM не
заведено поле `ALFACRM_FIELD_FREEZES`, счётчик ведётся в базе бота. Бот
предупреждает об этом в логе один раз и работает дальше.

**Кнопки не отвечают.** Скорее всего это старое сообщение из истории
чата от предыдущей версии бота — бот отвечает на такие явным «кнопка
устарела». Отправьте `/start`.
